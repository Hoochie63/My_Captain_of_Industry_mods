v0.8.0 | 2026-08-17
* 感谢中国玩家 五毛辣条(523004259) 反馈的bug.
* 修复：OverclockingMod 共存时 4 缓冲区不显示（核心修复）
  问题：单独加载 MyAirshipMod 时地面停机坪 4 个缓冲区正常，但只要加上 OverclockingMod，停机坪瞬间只显示 1 个主存储区。
  根因：HelipadInspectorRedirect 在 Initialize 阶段手动 new 了一个 StorageInspector 单例，跳过了 Harmony 的 CtorPostfix（构造函数补丁），所以辅助槽面板从未被创建。同时，由于单例不在 InspectorsManager 的正常生命周期里  ，Activate(entity) 后 OnActivatedPostfix 也不触发。单独跑时还能凑合，加上 OverclockingMod 后对方 patch 了 Inspector 基类调用链，把这个脆弱的凑合也给打破了。
* 修复：在 HelipadInspectorRedirect.cs 的 TryActivateForPrefix 命中 Helipad 并调用 Activate(entity) 后，主动调用 HelipadInspectorPatch.EnsurePanelsForHelipad(s_helipadInspector)，不再依赖游戏框架触发   CtorPostfix/OnActivatedPostfix，保证 3 个辅助槽面板 + 端口映射面板被创建，并启动 500ms Schedule 持续刷新。
* 修复：辅助缓冲区存档加载丢失（严重 bug）
  问题：保存游戏后重新读档，3 个辅助缓冲区的产品类型和数量全部丢失，只有主缓冲区被保留。
  根因：HelipadSaveLoad.cs 的 ParseBufferLine 和 ParsePortLine 存在数组索引越界——存档格式是 entityId:slotIndex=productId,quantity（只有 2 段），但解析代码写成了 header[4]、parts[4]、data[4]（应为 header[1]、parts  [1]、data[1]）。每次解析都抛 IndexOutOfRangeException，被 catch { } 静默吞掉，所以永远加载不出来。
* 修复：纠正所有索引：header[4]→header[1]、parts[4]→parts[1]、data[4]→data[1]
  Split 时用 Split(new[] {'='}, 2) 避免产品 ID 里有 = 被误伤
  保存格式升级 v2：缓冲区一行从 entityId:slotIndex=productId,quantity 升级为 entityId:slotIndex=productId,quantity,capacity（多带 capacity），加载时向后兼容 v1 格式
  ParseBufferLine 返回 bool、ParsePortLine 返回 int，LoadAll 统计已加载条数
  失败时打印 Warning（含原始 line 内容），不再 silent swallow
* 修复：AirshipHQManager 编译错误
  问题：AirshipHQManager.cs 同时引入了 Mafi.Core 和 UnityEngine 两个命名空间，两者都有 EntityId 类型，导致 12 处 EntityId 引用产生二义性编译错误。
* 修复：在 AirshipHQManager.cs 顶部 using 区添加别名 using EntityId = Mafi.Core.EntityId;，统一指向 Mafi 的 EntityId。
* 修复：BufferWithSlider 初值硬编码
  问题：HelipadInspectorPatch.cs 的 CreateHelipadPanels 里 BufferWithSlider 初值硬编码为 new Quantity(500000)。
  修复：改为引用 HelipadMultiBufferManager.DEFAULT_EXTRA_CAPACITY，避免后续调整辅助缓冲区容量时漏改。
* 修复：清理调试日志
  移除以下文件中的刷屏级 -Debug 诊断日志，只保留 Error / Warning 和存档结果日志：
  MyAirshipMod.cs：RegisterPrototypes 11 步成功日志

  HelipadInspectorPatch.cs：ApplyPatch/PatchOnActivated/CtorPostfix/OnActivatedPostfix/EnsurePanelsForHelipad 成功日志、UpdatePanelVisibility 状态变化诊断、Dictionary<int,int> / HashSet<int> 去重容器
  HelipadInspectorRedirect.cs：Initialize/ApplyPatch/TryActivateForPrefix 成功日志、HashSet<int> 去重容器  
  保留的日志：

* Thanks to Chinese player 五毛辣条(523004259) for reporting the bug.
* Fix: 4‑buffer display failure when OverclockingMod is present (core fix)
  Issue: The 4 buffers on the ground helipad work correctly when MyAirshipMod runs alone. However, once OverclockingMod is enabled, only 1 main storage area is shown on the helipad.
  Root Cause: HelipadInspectorRedirect manually instantiated a StorageInspector singleton during the Initialize phase, bypassing Harmony’s CtorPostfix (constructor patch). As a result, auxiliary slot panels were never created. Furthermore, since this singleton lived outside the normal lifecycle of InspectorsManager, OnActivatedPostfix would not fire after Activate(entity). The setup barely worked on its own, but adding OverclockingMod broke this fragile workaround because the mod patched the Inspector base‑class call chain.
* Fix: After TryActivateForPrefix in HelipadInspectorRedirect.cs matches a Helipad and calls Activate(entity), explicitly invoke HelipadInspectorPatch.EnsurePanelsForHelipad(s_helipadInspector). Remove reliance on the game framework to trigger CtorPostfix / OnActivatedPostfix. This guarantees creation of the 3 auxiliary‑slot panels plus the port‑mapping panel, and starts a 500ms Schedule for continuous refreshing.
* Fix: Auxiliary buffers data lost on save‑game load (critical bug)
  Issue: After saving and reloading a save file, product types and quantities for all 3 auxiliary buffers are lost; only the main buffer remains intact.
  Root Cause: Array index out‑of‑bounds errors in ParseBufferLine and ParsePortLine within HelipadSaveLoad.cs. The save format is entityId:slotIndex=productId,quantity (two segments only), yet the parsing code accessed header[4], parts[4], data[4] (should be header[1], parts[1], data[1]). Each parse threw an IndexOutOfRangeException which was silently swallowed by catch { }, so the data never loaded.
* Fix: Correct all indices: header[4] → header[1], parts[4] → parts[1], data[4] → data[1].
  Use Split(new[] {'='}, 2) during splitting to prevent unintended parsing when product IDs contain '=' characters.
  Save format upgraded to v2: each buffer line changes from entityId:slotIndex=productId,quantity to entityId:slotIndex=productId,quantity,capacity (added capacity field). Loader maintains backward compatibility with v1 format.
  ParseBufferLine now returns bool, ParsePortLine returns int; LoadAll counts successfully loaded entries.
  Print Warning (including the raw line content) on failure instead of silent swallowing.
* Fix: Compilation error in AirshipHQManager
  Issue: AirshipHQManager.cs imports both Mafi.Core and UnityEngine namespaces. Both define an EntityId type, causing ambiguous reference compile errors at 12 EntityId usages.
* Fix: Add alias `using EntityId = Mafi.Core.EntityId;` in the top‑level using block of AirshipHQManager.cs to uniformly reference Mafi’s EntityId.
* Fix: Hard‑coded initial value in BufferWithSlider
  Issue: In CreateHelipadPanels of HelipadInspectorPatch.cs, BufferWithSlider was hard‑initialized as new Quantity(500000).
* Fix: Reference HelipadMultiBufferManager.DEFAULT_EXTRA_CAPACITY instead, to avoid missing updates when adjusting auxiliary‑buffer capacity in the future.
* Fix: Clean up debug logs
  Remove spam‑heavy‑Debug diagnostic logs from the listed files; keep only Error / Warning logs and save‑game result logs:
  MyAirshipMod.cs: RegisterPrototypes 11‑step success logs
  HelipadStorageHooks.cs: patch‑binding success logs, first‑time per‑entity logs for CanReceive/ReceiveFromPort, HashSet<int> deduplication containers
  HelipadInspectorPatch.cs: success logs for ApplyPatch/PatchOnActivated/CtorPostfix/OnActivatedPostfix/EnsurePanelsForHelipad, state‑change diagnostics for UpdatePanelVisibility, Dictionary<int,int> / HashSet<int> deduplication containers
  HelipadInspectorRedirect.cs: success logs for Initialize/ApplyPatch/TryActivateForPrefix, HashSet<int> deduplication containers
  Preserved logs:
  Save‑game save / load results: [MyAirshipMod] HelipadSaveLoad Saved / Loaded: Auxiliary buffers=X entries, Port mappings=Y entries
  All Error / Warning logs (binding failures, reflection failures, parse failures with raw line content)
